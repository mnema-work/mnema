Changed

- **`status`, `brief`, the hooks, the edit gate and the server's tools refuse a symbolic link in a record, and open nothing it points at.** Until now only `verify` did: a segment, `checkpoints.jsonl`, `tailproof.json`, a key file or a witness file replaced by a link was followed by every other read, so the bytes of a file outside the repository could be served as the record, and a tail that was a link vanished from them in silence. Each of those reads now stops at the link and says where it is (`tails/<tail>/000001.jsonl is a symbolic link, and a record is read from its own files and directories: ...`) with the way out, which is to replace the link with the folder or file it points to. The refusal is the one a line that cannot be read already gets, so for now a read stops there instead of serving what is left, a write is refused (the file the link points at is not touched), and the edit gate denies. A link to a pipe no longer hangs a command, and a cache that remembers a segment is not believed over one that became a link. Making a read serve the rest of a record that holds a link is a later change; the record's root and the folders above it are not judged.
