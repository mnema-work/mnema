Changed

- **Every write is refused while an entry of the record is altered.** An entry whose content was changed in the file by hand (the hash it stores left alone) is left out of every read and said first, and a write over it used to go on and sign a new entry on top of a record that no longer proves itself. Every write is now refused until the line is as it was written, switching a channel off included, which is a write to the same record: the command line says `Refused (ALTERED_ENTRY)`, the agent's tools answer it with the fact not recorded (and a session that ends over such an entry leaves its run open instead of signing the end of it), the SDK returns it as a refusal, and the verbs that write for a hook (the copy of a note of the host's memory among them) refuse the same way. The refusal names the tree, the tail, the file and the line, and nothing is written, the record byte for byte as it was. In the public tree the way out is to restore the line from the repository's history; in the private tree and the global one, which no repository keeps, to restore the file from a copy or to repair or remove the line, and the refusal reaches every project of the machine when the line is in the global tree, as a line that cannot be read does. What still answers: the reads, the edit gate (which has its own denial), the agent's server itself (each tool that writes is refused at its own door), and the verbs that append nothing: the listing of `switch` and of `witness`, `inherit` without `--write`, `doctor` except `--fix private-tree`, `tail list`, `key restore`, `key protect`, `key unprotect`, `record pull`, `record merge-tail` and the `commit-hook` verbs. A gap and a fork are still told and never refused. The check and the append are two steps, and an alteration made between them is not seen.
