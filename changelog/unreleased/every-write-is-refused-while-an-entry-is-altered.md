Changed

- **Every write is refused while an entry of the record is altered.** An entry whose content was changed in the file by hand (the hash it stores left alone) is left out of every read and said first, and a write over it used to go on and sign a new entry on top of a record that no longer proves itself. Every write is now refused until the line is as it was written, `mnema switch off` included, which is a write to the same record: the command line says `Refused (ALTERED_ENTRY)` and the agent's tools answer it with the fact not recorded, and the hooks that write (the copy of a note of the host's memory, the corrections of a session) refuse the same way and the line reaches the model through the hook. The refusal names the tree, the tail, the file and the line, and nothing is written, the record byte for byte as it was. In the public tree the way out is to restore the line from the repository's history; in the private tree and the global one, which no repository keeps, to restore the file from a copy or to repair or remove the line, and the refusal reaches every project of the machine when the line is in the global tree, as a line that cannot be read does. The verbs that declare they can write and append nothing (`tail list`, `key restore`, `key request`, `key protect`, `key unprotect`) and the edit gate, which has its own denial, still answer. A gap and a fork are still told and never refused.
